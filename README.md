### 1. 基礎概念

| 用語（日文） | 中文說明 |
|---|---|
| 平文（ひらぶん） | 明文，尚未加密的原始資料 |
| 暗号化 | 加密。用暗号鍵將明文轉換成第三者無法讀懂的密文 |
| 復号 | 解密。用復号鍵將密文還原成明文 |
| 暗号鍵／復号鍵 | 加密鍵／解密鍵。依方式不同，可能是同一把鍵，也可能是不同的兩把鍵 |

⚠️ **考試重點**：判斷「暗号鍵」與「復号鍵」是否相同，是分辨共通鍵暗号方式 vs 公開鍵暗号方式的關鍵。

### 2. CRYPTREC 暗号リスト

**CRYPTREC**（Cryptography Research and Evaluation Committees）
＝日本総務省・経済産業省主導的**密碼技術安全性評估與監督機構**

#### 三種分類清單

| リスト名（日文） | 中文說明 |
|---|---|
| 電子政府推奨暗号リスト | 已確認安全性與實績，推薦政府系統採用的密碼技術（如 AES、RSA、SHA-256） |
| 推奨候補暗号リスト | 有實績、未來可能被納入推薦清單的候補演算法 |
| 運用監視暗号リスト | 已出現安全疑慮，僅限維持既有系統相容性使用，**不建議新系統採用** |

> ⚠️ **超頻出陷阱**：CRYPTREC 是「**評估・推薦**」機構，**不是**開發密碼演算法的機構。

### 3. 共通鍵暗号方式（對稱式加密）

- 加密與解密使用**同一把鍵（共通鍵）**
- 又稱：**秘密鍵暗号方式**（注意：此處「秘密鍵」與公開鍵暗号方式中的「秘密鍵」概念不同，考試易混淆）

#### 特徵

| 項目 | 內容 |
|---|---|
| ✅ 優點 | 處理速度快 |
| ❌ 缺點 | 鍵配送問題（如何安全地把鍵傳給對方） |
| 代表方式 | **AES（Advanced Encryption Standard，進階加密標準）**＝ブロック暗号（Block Cipher，區塊加密）的一種 |

#### 鍵數量公式（超頻出）

n 人相互通訊時，所需共通鍵總數：

```
n × (n − 1) ÷ 2
```

例：5人相互通訊 → 5×4÷2 = **10把**

---

### 4. 公開鍵暗号方式（非對稱式加密）

- 使用**公開鍵**（任何人皆可取得）與**秘密鍵**（僅本人持有）成對的鍵
- 用公開鍵加密的資料，只有對應的秘密鍵能解開

#### 特徵

| 項目 | 內容 |
|---|---|
| ✅ 優點 | 不需事先共享鍵，解決鍵配送問題 |
| ❌ 缺點 | 處理速度比共通鍵暗号方式慢 |
| 代表方式 | **RSA暗号**（利用大數質因數分解的困難度） |

#### 依用途區分使用（超重要）

| 目的 | 加密時使用的鍵 |
|---|---|
| 🔒 秘密通訊（只想讓對方讀取） | 使用**對方的公開鍵**加密 |
| ✍️ 電子署名（デジタル署名｜Digital Signature，證明是自己發送） | 使用**自己的秘密鍵**加密（簽署） |

> ⚠️ **超頻出陷阱**：「A要傳機密資訊給B時，該用誰的鍵？」→ 正解是 **B的公開鍵**

---

### 5. ハイブリッド暗号方式（Hybrid Encryption｜混合式加密）

共通鍵暗号（速度快）＋公開鍵暗号（鍵配送安全）的**優點結合**

#### 處理流程

```
① 傳送的資料本體 → 用共通鍵加密（高速處理）
② 該共通鍵本身 → 用接收者的公開鍵加密（安全傳遞鍵）
③ 將「加密後的資料」＋「加密後的共通鍵」一起傳送
④ 接收者：用自己的秘密鍵解開共通鍵 → 再用該共通鍵解密資料本體
```

**實例：SSL/TLS 通訊**（HTTPS）即採用此方式。

---

### 6. ハッシュ関数（Hash Function｜雜湊函數）

將任意長度的資料 → 轉換成**固定長度的雜湊值（ダイジェスト｜Digest）**

#### 特性

- ✅ 相同輸入 → 必得相同輸出
- ✅ **不可逆**（無法從雜湊值還原原始資料）
- ✅ 高抗碰撞性（不同輸入產生相同雜湊值的機率極低）

#### 代表方式

**SHA-256**（SHA-2 家族，Secure Hash Algorithm）

#### 用途

| 用途 | 說明 |
|---|---|
| 竄改檢測（改ざん検知｜Tampering Detection） | 比對檔案的雜湊值，確認內容是否遭到變更 |
| 密碼儲存 | 儲存雜湊值而非密碼原文 |
| 電子署名 | 對訊息的雜湊值進行簽章 |

> ⚠️ **超頻出陷阱**：「雜湊函數是一種可還原的加密方式」→ **錯誤**。雜湊不可逆，屬於「完整性驗證」技術，並非「加密」。

---

### 7. 暗号利用モード（Mode of Operation｜加密運用模式）

區塊加密（AES等）只能處理固定長度區塊，處理較長資料時需要「模式」串接多個區塊。

| モード（模式） | 特徵 |
|---|---|
| **ECB**（Electronic Codebook，電子密碼本模式） | 各區塊獨立加密。相同明文區塊會產生相同密文區塊，容易被分析，安全性較低 |
| **CBC**（Cipher Block Chaining，密碼區塊鏈結模式） | 每個區塊加密前，先與前一個密文區塊做 XOR 運算。安全性比 ECB 高 |

### 8. 比較表まとめ｜比較總表

| 項目 | 共通鍵暗号方式（對稱式） | 公開鍵暗号方式（非對稱式） |
|---|---|---|
| 鍵的數量 | 同一把鍵 | 公開鍵・秘密鍵成對，共2把 |
| 處理速度 | 快 | 慢 |
| 鍵配送問題 | 有（弱點） | 無 |
| 代表演算法 | AES | RSA |
| n人相互通訊所需鍵數 | n(n-1)/2 | 2n（各自持有一組鍵對） |

### 10. 記憶のコツ｜記憶口訣

- 🔑 **共通鍵（きょうつうかぎ）** ＝ 一把鑰匙雙方共用 → **速度快，但鍵配送困難**
- 🔓🔒 **公開鍵（こうかいかぎ）** ＝ 公開的鎖＋本人專屬的鑰匙 → **速度慢，但無鍵配送問題**
- 📨 **用公開鍵加密 → 秘密通訊**（使用對方的鍵）
- ✍️ **用秘密鍵加密 → 電子署名**（使用自己的鍵＝證明本人身分）
- 🧬 **ハッシュ（Hash）＝ 只能驗證，無法還原**（不是加密）
- 🏛️ **CRYPTREC ＝ 評估與推薦機構**（不是開發機構）

### 1. 監査業務

| 業務監査 | 業務稽核，針對業務執行狀況進行的稽核 |

### 2. システム監査の目的と手順

#### ① システム監査の目的（系統稽核的目的）

系統稽核的目的：由具備高度倫理觀、**獨立且客觀**立場的**システム監査人（系統稽核人員｜System Auditor）**，針對資訊系統相關風險是否獲得適當因應進行**檢證・評估**，透過提供保證或建議，支援組織的經營活動與業務活動能有效率地推行，並促進組織達成目標，同時對利害關係人（ステークホルダ｜Stakeholder）盡到說明責任（**アカウンタビリティ｜Accountability**）。

| 用語（日文） | 中文說明 |
|---|---|
| システム監査人の権限と責任 | 系統稽核人員的權限與責任 |
| 監査人の倫理 | 稽核人員的職業倫理 |
| 誠実性 | 誠實正直 |
| 専門的能力の保持と向上 | 維持並提升專業能力 |
| 正当な注意と秘密の保持 | 正當注意義務與保密義務 |
| 監査の独立性と客観性の保持 | 維持稽核的獨立性與客觀性 |

> ⚠️ **考試重點**：システム監査人必須具備「**獨立性**」與「**客觀性**」——不能稽核自己負責的業務（獨立性），且判斷不能受主觀偏見影響（客觀性）。

#### ② システム監査の流れ（系統稽核的流程）

系統稽核依循以下流程進行：

```
① 監査計画の策定（擬定稽核計畫）
   ↓
② 監査の実施（執行稽核）
   ↓
③ 監査報告（稽核報告）
   ↓
④ フォローアップ（Follow-up｜後續追蹤）
```

| 用語（日文） | 中文說明 |
|---|---|
| リスクアプローチ（Risk Approach） | 風險導向法，依風險評估結果來擬定監査計画 |
| 監査証拠の入手と評価 | 取得並評估稽核證據 |
| 監査調書の作成と保管 | 製作並保存稽核工作底稿 |
| 監査の結論の形成 | 形成稽核結論 |
| 監査報告書の作成と報告 | 製作稽核報告書並提出報告 |
| 改善提案のフォローアップ | 對改善建議進行後續追蹤 |

### 3. システム監査の対象業務

系統稽核的對象範圍，不僅限於資訊系統的**コントロール（Control｜控制）**與**マネジメント（Management｜管理）**，還擴及到**ガバナンス（Governance｜治理）**層面。

#### 涵蓋範圍

- 資訊系統的**企画（規劃）・開発（開發，含アジャイル開発｜Agile Development｜敏捷開發）・運用（運行）・保守（維護）・廃棄（汰換）**流程
- 外部服務的**調達（採購）・利活用（活用）**流程

> 📌 系統稽核實施的目的與範圍，須透過**監査規程**、**契約書**等文件及**監査計画**明確訂定。

| 用語（日文） | 中文說明 |
|---|---|
| リスク（Risk） | 風險 |
| コントロール（Control） | 控制 |
| 内部監査規程 | 內部稽核規範 |
| システム監査委託契約書 | 系統稽核委託契約書 |

---

### 4. システム監査計画の策定

為了進行有效且有效率的稽核，システム監査人須擬定包含以下項目的**監査計画**：

- 監査の目的・テーマ（稽核目的與主題）
- 監査対象範囲（稽核對象範圍）
- 監査の方法（稽核方法）
- 実施時期（實施時程）
- 実施体制（執行體制）
- 実施スケジュール（執行排程）

---

### 5. システム監査の実施（予備調査，本調査，評価，結論）

システム監査人依據監査計画進行充分調查，並對系統進行**檢證・評估**。

#### 實施階段

| 階段（日文） | 中文說明 |
|---|---|
| 予備調査 | 事前調查，先了解稽核對象的概況與環境 |
| 本調査 | 正式調查，深入蒐集並驗證證據 |
| 評価 | 評估，依取得的證據評估控制是否有效 |
| 結論 | 結論，形成最終稽核意見 |

| 用語（日文） | 中文說明 |
|---|---|
| 監査手続の適用 | 執行監査程序 |
| 監査証拠の入手と評価 | 取得並評估監査證據 |
| 監査調書の作成と保管 | 製作並保存監査工作底稿 |
| 代表的なシステム監査技法 | 常見的系統監査技術（如：訪談法、文件檢閱法、電腦輔助稽核技術CAAT等） |

---

### 6. システム監査の報告とフォローアップ

システム監査人須以符合監査目的的適當形式，向監査依頼者及相關關係人**報告**監査結果。

#### 兩種監査類型

| 類型 | 說明 |
|---|---|
| 保証を目的としたシステム監査 | 以「保證」為目的的系統監査（確認控制有效並提供保證） |
| 助言を目的としたシステム監査 | 以「建議」為目的的系統監査（提供改善建議） |

#### フォローアップ（Follow-up｜後續追蹤）

針對報告書中記載的**指摘事項（指出的問題點）**與**改善提案**（或受稽核單位自行擬定的**改善計画**），確認是否已**適切且及時**地實施相關改善措施。

| 用語（日文） | 中文說明 |
|---|---|
| システム監査報告書 | 系統監査報告書 |
| 指摘事項 | 稽核中指出的問題點 |
| 改善提案 | 改善建議 |
| 改善計画 | 改善計畫（通常由受稽核方擬定） |
| フォローアップ報告書 | 後續追蹤報告書 |

須建立並運用相關體制，以確保系統監査能滿足各方需求，並維持一定的**監査品質**。

## 1. 電気・電子回路（電子電路）

理解電腦基本邏輯電路——**AND 回路**、**OR 回路**、**NOT 回路**等的動作原理。

| 用語（日文） | 中文說明 |
|---|---|
| AND 回路 | 及閘，兩輸入皆為1時輸出1 |
| OR 回路 | 或閘，任一輸入為1時輸出1 |
| NOT 回路 | 反閘，輸出與輸入相反 |
| NAND 回路（NAND Gate） | 反及閘，AND閘輸出取反（萬用邏輯閘，可組合出所有其他邏輯閘） |
| フリップフロップ（Flip-Flop） | 正反器，可儲存1位元資料的基本記憶電路元件（時序邏輯電路的基礎） |
| 論理式（Logical Expression） | 邏輯運算式 |
| 正論理（Positive Logic） | 正邏輯，高電位＝1，低電位＝0 |
| 負論理（Negative Logic） | 負邏輯，高電位＝0，低電位＝1 |
| 真理値表（Truth Table） | 真值表，列出所有輸入組合對應輸出結果的表格 |

> ⚠️ **考試重點**：給定真理値表或邏輯式，判斷是哪種邏輯閘（AND/OR/NAND/NOT）；NAND閘為「萬用閘」可組成任意邏輯電路的概念也常出題。

## 2. 機械・制御（機械・控制）

理解代表性的機械電子控制之基本動作原理。

| 用語（日文） | 中文說明 |
|---|---|
| オープンループ制御（Open-loop Control） | 開迴路控制，不將輸出結果回饋至輸入端，僅依預設程序執行（無回饋修正） |
| クローズドループ制御（Closed-loop Control） | 閉迴路控制，將輸出結果回饋比較，依誤差調整輸入（有回饋修正） |
| シーケンス制御（Sequence Control） | 順序控制，依預先決定的順序逐步執行控制動作 |
| フィードバック制御（Feedback Control） | 回饋控制，偵測輸出與目標值的偏差，並據以修正輸入，屬於閉迴路控制的核心概念 |
| PWM（Pulse Width Modulation｜脈衝寬度調變）制御 | 脈衝寬度調變控制，透過改變脈衝訊號的「寬度（Duty Cycle）」來控制輸出功率（如馬達轉速、LED亮度調整） |

> ⚠️ **考試重點**：
> - **オープンループ制御** vs **クローズドループ制御**：有無回饋機制是關鍵區別
> - **フィードバック制御** ＝ クローズドループ制御 的具體實現方式
> - **PWM制御** 常見於馬達控速、電源供應器等應用場景的敘述判斷題

## 3. 構成部品及び要素と実装（構成元件與實裝）

理解代表性的構成元件、要素及其實裝方式。

| 用語（日文） | 中文說明 |
|---|---|
| ダイオード（Diode） | 二極體，具備單向導電特性的基本電子元件 |
| LED（Light Emitting Diode） | 發光二極體 |
| トランジスタ（Transistor） | 電晶體，可用於訊號放大或開關控制的半導體元件 |
| IC（Integrated Circuit） | 積體電路，將多個電子元件整合於單一晶片上 |
| LSI（Large Scale Integration） | 大型積體電路 |
| VLSI（Very Large Scale Integration） | 超大型積體電路，積體度比LSI更高 |
| FPGA（Field Programmable Gate Array） | 現場可程式化邏輯閘陣列，出廠後仍可依需求重新燒錄邏輯電路架構的可程式化晶片 |

## 8. 記憶のコツ｜記憶口訣

- 🔌 **AND** ＝ 兩個都要（都是1才行）；**OR** ＝ 有一個就好；**NOT** ＝ 唱反調
- 🌀 **NAND** ＝ 萬能積木，可以拼出所有其他邏輯閘
- 🔁 **クローズドループ** ＝ 有「回頭看」機制（回饋比較修正）；**オープンループ** ＝ 「有去無回」，不管結果對不對
- 💡 **PWM** ＝ 用「開關的快慢與寬度」來控制強弱，像眨眼頻率控制亮度
- 📏 **IC < LSI < VLSI** ＝ 積體電路的「小、中、大」三兄弟，越後面塞的電晶體越多
- 🧱 **FPGA** ＝ 「可以重新拼裝的樂高積木晶片」，出廠後還能重新設計電路邏輯

| 多次元配列（Multi-dimensional Array） | 多維陣列，如二維陣列（表格狀） |
| 静的配列（Static Array） | 靜態陣列，大小在編譯時期就固定，執行中無法變更 |
| 動的配列（Dynamic Array） | 動態陣列，大小可在執行時期彈性調整 |

> ⚠️ **考試重點**：陣列的優點是可依索引直接存取（O(1)），但插入/刪除中間元素需要搬移大量資料（效率較低）。

### 1-2. リスト（List｜串列）

理解串列的基本概念與操作。

| 用語（日文） | 中文說明 |
|---|---|
| 線形リスト（Linear List） | 線性串列，元素依序排列，每個節點指向下一個節點 |
| 単方向リスト（Singly Linked List） | 單向串列，每個節點只有指向「下一個」節點的指標 |
| 双方向リスト（Doubly Linked List） | 雙向串列，每個節點同時具備指向「前一個」與「下一個」節點的指標 |
| 環状リスト（Circular List） | 環狀串列，最後一個節點指回第一個節點，形成環狀結構 |

> ⚠️ **考試重點**：串列插入/刪除元素只需改變指標指向（不需搬移資料），比陣列有效率；但無法像陣列一樣直接依索引存取（需從頭走訪，O(n)）。

### 1-3. スタックとキュー（Stack and Queue｜堆疊與佇列）

理解堆疊與佇列的特徵及基本操作。

| 用語（日文） | 中文說明 |
|---|---|
| FIFO（First In First Out） | 先進先出，佇列（Queue）的存取原則 |
| LIFO（Last In First Out） | 後進先出，堆疊（Stack）的存取原則 |
| プッシュ（Push） | 推入，將資料放入堆疊頂端的操作 |
| ポップ（Pop） | 彈出，取出堆疊頂端資料的操作 |

| 結構 | 存取原則 | 常見應用 |
|---|---|---|
| スタック（Stack｜堆疊） | LIFO（後進先出） | 函式呼叫堆疊、瀏覽器上一頁功能、括號匹配檢查 |
| キュー（Queue｜佇列） | FIFO（先進先出） | 工作排程、印表機列印佇列、訊息佇列 |

> ⚠️ **考試重點**：給定一連串的 プッシュ/ポップ 或 エンキュー(Enqueue)/デキュー(Dequeue) 操作序列，判斷最終輸出順序，是必考計算題。

### 1-4. 木構造（Tree Structure｜樹狀結構）

理解樹狀結構的種類與特徵、樹的**巡回法（Traversal｜走訪法）**、節點的新增與刪除、**ヒープ（Heap｜堆積）**的重新調整等。

| 用語（日文） | 中文說明 |
|---|---|
| 根（Root） | 根節點，樹的最頂端節點 |
| 葉（Leaf） | 葉節點，沒有子節點的末端節點 |
| 枝（Branch/Edge） | 分支，連接節點之間的邊 |
| 2 分木（Binary Tree） | 二元樹，每個節點最多只有兩個子節點 |
| 完全 2 分木（Complete Binary Tree） | 完全二元樹，除最後一層外，其他層都填滿節點，且最後一層由左至右填滿 |
| バランス木（Balanced Tree） | 平衡樹，左右子樹高度差維持在一定範圍內，確保搜尋效率 |
| 順序木（Ordered Tree） | 有序樹，子節點之間有明確順序關係 |
| 多分木（Multiway Tree） | 多元樹，每個節點可有多個子節點（超過兩個） |
| 探索木（Search Tree） | 搜尋樹，用於快速搜尋資料的樹狀結構 |
| 2 分探索木（Binary Search Tree, BST） | 二元搜尋樹，左子樹所有節點值 < 父節點 < 右子樹所有節點值 |
| B 木（B-Tree） | B樹，一種多路平衡搜尋樹，常用於資料庫與檔案系統索引 |
| AVL 木（AVL Tree） | AVL樹，一種自平衡二元搜尋樹，任一節點左右子樹高度差不超過1 |
| 深さ優先探索（Depth-First Search, DFS） | 深度優先搜尋，優先往深處探索，走到底再回頭 |
| 幅優先探索（Breadth-First Search, BFS） | 廣度優先搜尋，先探索同一層的所有節點，再往下一層 |
| 先行順（Preorder） | 前序走訪：根 → 左子樹 → 右子樹 |
| 後行順（Postorder） | 後序走訪：左子樹 → 右子樹 → 根 |
| 中間順（Inorder） | 中序走訪：左子樹 → 根 → 右子樹 |

> ⚠️ **考試重點**：
> - **前序（先行順）／中序（中間順）／後序（後行順）** 走訪順序判讀是超頻出題型——給一棵二元樹，寫出三種走訪結果
> - **2分探索木** 的搜尋、插入、刪除操作邏輯
> - **DFS** vs **BFS** 使用的資料結構不同：DFS常用「スタック」（或遞迴），BFS常用「キュー」
> - **B木**、**AVL木** 常出現在「為何需要平衡樹」的概念題（避免搜尋樹退化成線性串列，維持O(log n)搜尋效率）

### 2-2. 整列・併合・探索のアルゴリズム（排序・合併・搜尋演算法）

理解排序演算法、合併演算法、搜尋演算法的基本設計方法。

#### 排序演算法（整列のアルゴリズム）

| 用語（日文） | 中文說明 | 平均時間複雜度 |
|---|---|---|
| 選択ソート（Selection Sort） | 選擇排序，每次從未排序區間選出最小（大）值放到已排序區間末端 | O(n²) |
| バブルソート（Bubble Sort） | 泡沫排序，相鄰元素兩兩比較並交換，逐步將大值「浮」到後方 | O(n²) |
| マージソート（Merge Sort） | 合併排序，將序列不斷對半分割後再合併排序（分治法） | O(n log n) |
| 挿入ソート（Insertion Sort） | 插入排序，將元素依序插入已排序區間的正確位置 | O(n²) |
| シェルソート（Shell Sort） | 希爾排序，插入排序的改良版，先以較大間隔分組排序再逐步縮小間隔 | O(n^1.25) 左右（依實作） |
| クイックソート（Quick Sort） | 快速排序，選定基準值（Pivot）將序列分為兩部分再遞迴排序（分治法） | O(n log n)（平均） |
| ヒープソート（Heap Sort） | 堆積排序，利用堆積（Heap）資料結構的特性進行排序 | O(n log n) |

#### 搜尋演算法（探索のアルゴリズム）

| 用語（日文） | 中文說明 | 時間複雜度 |
|---|---|---|
| 線形探索法（Linear Search） | 線性搜尋，從頭到尾依序比對 | O(n) |
| 2 分探索法（Binary Search） | 二分搜尋，僅適用於「已排序」資料，每次將搜尋範圍對半縮減 | O(log n) |
| ハッシュ表探索法（Hash Table Search） | 雜湊表搜尋，透過雜湊函數直接計算資料儲存位置 | O(1)（理想狀況） |

> ⚠️ **考試重點**：
> - 各排序法的**時間複雜度**與**穩定性（安定性）**比較（哪些是穩定排序：バブル、挿入、マージ；哪些不穩定：選択、クイック、ヒープ）
> - 給定資料序列，手動模擬排序過程中「某一輪結束後」的中間結果，是超頻出計算題
> - **2分探索法** 必須先確認資料已排序才能使用，且每次搜尋範圍減半（考搜尋次數計算）
> - **クイックソート** 的Pivot選擇與分割過程常出圖表化步驟判讀題

### 2-3. 再帰のアルゴリズム（Recursive Algorithm｜遞迴演算法）

> 📝 常見範例：階乘計算、費氏數列、河內塔問題、二元樹的走訪（DFS）等，皆常以遞迴實作。

### 2-4. グラフのアルゴリズム（Graph Algorithm｜圖形演算法）

理解圖形演算法的基本概念。

| 用語（日文） | 中文說明 |
|---|---|
| 深さ優先探索（DFS） | 深度優先搜尋，適用圖形的走訪，常用堆疊或遞迴實作 |
| 幅優先探索（BFS） | 廣度優先搜尋，適用圖形的走訪，常用佇列實作 |
| 最短経路探索（Shortest Path Search） | 最短路徑搜尋 |
| ダイクストラ法（Dijkstra's Algorithm） | 戴克斯特拉演算法，求解「無負權重邊」圖形中單一起點到各節點的最短路徑 |
| ベルマンフォード法（Bellman-Ford Algorithm） | 貝爾曼-福特演算法，可處理「含負權重邊」的圖形，求解最短路徑（並可偵測負權重環） |

> ⚠️ **考試重點**：**ダイクストラ法** vs **ベルマンフォード法** 的適用條件差異——Dijkstra不能處理負權重邊，Bellman-Ford可以但速度較慢，是常見的比較題。

## 5. 記憶のコツ｜記憶口訣

- 📦 **スタック（Stack）＝ 疊盤子**，只能從最上面拿（後進先出LIFO）
- 🎫 **キュー（Queue）＝ 排隊買票**，先來的先服務（先進先出FIFO）
- 🌳 **先行・中間・後行順** ＝ 「根的位置」在走訪順序中的位置：先行＝根在前、中間＝根在中間、後行＝根在後
- 🔍 **DFS用堆疊（一路衝到底）；BFS用佇列（一層一層來）**
- 🫧 **バブルソート** ＝ 泡泡一個個浮上來（相鄰交換）
- ✂️ **マージ・クイック** ＝ 都是「分治法」，先切開再各自處理
- 🗺️ **ダイクストラ** ＝ 只走「正常路」（無負權重）；**ベルマンフォード** ＝ 連「負分路」都能算，只是比較慢
- 🔢 **2分探索法** ＝ 猜數字遊戲，每次都對半猜，前提是「數字要先排好序」

## 1. ネットワークトポロジ（Network Topology｜網路拓樸）

理解代表性的網路架構種類與特徵，以及端末（終端設備）與制御機器（控制設備）之間的連接形態。

| 用語（日文） | 中文說明 |
|---|---|
| ポイントツーポイント（Point-to-Point｜2 地点間接続） | 點對點連接，兩個端點直接一對一連線 |
| ツリー型（Tree Topology） | 樹狀拓樸，以階層方式分支連接，類似組織架構圖 |
| バス型（Bus Topology） | 匯流排型拓樸，所有裝置共用同一條主幹傳輸線 |
| スター型（Star Topology） | 星狀拓樸，所有裝置各自連接到中央集線器/交換器 |
| リング型（Ring Topology） | 環狀拓樸，裝置依序首尾相連形成封閉環路 |

### 各拓樸特徵比較

| 拓樸 | 連接方式 | 優點 | 缺點 |
|---|---|---|---|
| バス型 | 共用一條主幹線 | 佈線簡單、成本低 | 主幹線故障則全網癱瘓；訊號衝突風險 |
| スター型 | 各裝置獨立連至中央節點 | 單一裝置故障不影響其他裝置；易於管理 | 中央節點（集線器/交換器）故障則全網癱瘓 |
| リング型 | 裝置首尾相連成環 | 訊號傳輸方向固定，無衝突問題 | 環路中任一節點故障可能影響整體傳輸（視技術而定） |
| ツリー型 | 階層式分支連接 | 易於擴充與管理，符合組織架構 | 上層節點故障會影響下層所有分支 |

> ⚠️ **考試重點**：
> - **スター型** 是目前最主流的區域網路連接方式（透過交換器/Switch）
> - 各拓樸「單點故障（Single Point of Failure）」的影響範圍判斷是常見概念題
> - 給定圖形，判斷是哪一種トポロジ

## 2. OSI 基本参照モデル（OSI Reference Model｜OSI 基本參考模型）

理解由 **ISO**（International Organization for Standardization，國際標準化組織）制定的、由 **7層** 構成的網路架構——OSI基本參考模型，各層的基本功能，以及各層之間的關係。

### 七層結構（由上而下）

| 層級 | 日文名稱 | 中文說明 | 主要功能 |
|---|---|---|---|
| 第7層 | アプリケーション層（Application Layer） | 應用層 | 提供使用者直接使用的應用程式服務介面（如HTTP, FTP, SMTP） |
| 第6層 | プレゼンテーション層（Presentation Layer） | 表現層 | 資料格式轉換、加密/解密、壓縮/解壓縮，確保資料在不同系統間可被正確解讀 |
| 第5層 | セション層（Session Layer） | 會議層 | 建立、管理、結束通訊雙方的會話（Session），如連線的同步與恢復 |
| 第4層 | トランスポート層（Transport Layer） | 傳輸層 | 確保端對端資料傳輸的可靠性（如TCP的重傳機制、流量控制） |
| 第3層 | ネットワーク層（Network Layer） | 網路層 | 負責路徑選擇與邏輯定址（如IP位址、路由） |
| 第2層 | データリンク層（Data Link Layer） | 資料鏈結層 | 負責同一網段內的訊框傳輸、錯誤偵測（如MAC位址、乙太網路） |
| 第1層 | 物理層（Physical Layer） | 實體層 | 負責實體訊號傳輸（如電壓、光訊號、纜線、接頭規格） |

### 記憶用口訣圖示

```
第7層 アプリケーション層   ← 使用者看得到的（Email, 網頁）
第6層 プレゼンテーション層 ← 資料「長相」轉換（編碼/加密）
第5層 セション層           ← 對話的「起訖」管理
第4層 トランスポート層     ← 保證資料「送達」（TCP/UDP）
第3層 ネットワーク層       ← 決定資料走「哪條路」（IP/路由）
第2層 データリンク層       ← 同一區網內的「傳遞」（MAC）
第1層 物理層               ← 最底層的「電訊號/光訊號」
```

> ⚠️ **考試重點**：
> - **7層順序**必須熟記（由下而上或由上而下皆可能出題）
> - 給定通訊協定（如TCP, IP, HTTP, Ethernet），判斷對應到OSI模型的哪一層
> - 各層的**代表性設備**對應：
>   - 物理層 → Hub（集線器）、リピータ（中繼器）
>   - データリンク層 → スイッチ（交換器）、ブリッジ（橋接器）
>   - ネットワーク層 → ルータ（路由器）
> - **カプセル化（封裝，Encapsulation）**：資料從上層往下層傳遞時，每層會加上該層的標頭（Header）資訊

## 5. 記憶のコツ｜記憶口訣

- 🚌 **バス型** ＝ 大家共擠一輛公車（一條線），公車拋錨全部人受影響
- ⭐ **スター型** ＝ 每個人各自牽線到「總機中心」，總機掛了大家才斷線
- 💍 **リング型** ＝ 大家手牽手圍成一圈，訊息傳一圈
- 🌲 **ツリー型** ＝ 像公司組織圖，一層一層往下分支

**OSI七層口訣（由第7層到第1層）**：
「應（application）表（presentation）會（session）傳（transport）網（network）資（data link）物（physical）」
可以聯想成：**「應用表演，會議傳網路，資料物理」**

- 📮 **物理層** ＝ 郵差開的「車」（實體傳輸媒介）
- 🏷️ **データリンク層** ＝ 信封上的「門牌地址（同社區內）」（MAC位址，區域內定址）
- 🗺️ **ネットワーク層** ＝ 跨城市的「路線規劃」（IP位址與路由）
- 📦 **トランスポート層** ＝ 確保「包裹有沒有送達」（TCP可靠傳輸）
- 🎬 **セション層** ＝ 通話的「開始與掛斷」
- 🎨 **プレゼンテーション層** ＝ 把資料「翻譯成大家看得懂的格式」
- 🖥️ **アプリケーション層** ＝ 使用者直接看到的「軟體畫面」
